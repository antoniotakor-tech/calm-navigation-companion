# Visual Redesign — 2026-07-29

## What this was

A full visual redesign to match the design language, polish, and motion quality of a
reference claude.ai artifact, without changing any existing app functionality — plus one
functional addition: the Kalimba is now always playable, with leaving an Echo gated
behind the existing 500m/3min exploration unlock.

## Honest disclosure on the reference extraction

The reference artifact required claude.ai sign-in; I do not enter credentials, so I never
signed in. Once the repo was made public, the embedded content still rendered inside a
cross-origin iframe (`*.frame.claudeusercontent.com`) that DOM/JS inspection tools cannot
traverse (standard same-origin policy) — so I extracted the design language visually
(screenshots + window resizing to reveal more of the page), not from computed styles or
markup. I was able to reach the hero section, header treatment, primary CTA, and an
auto-cycling phone mockup. I could **not** get a working scroll on the reference page
(scroll timed out repeatedly; resizing to extreme heights eventually hit a blank gap
suggesting scroll-triggered section reveals that a raw resize doesn't replay), so I never
saw whatever "Story," "Features," or "Beta" sections exist further down. Everything below
is grounded in what I could actually see, not invented.

What I read off the reference and carried over as *tokens*, not copied elements:
- Typography pairing: a light-weight serif for one hero/display moment + a bold neutral
  sans for headings + a clean sans for body copy.
- A calm, editorial palette (soft cream background, muted sage/coral/lavender accents)
  rather than a bright/saturated one.
- Flat gradient pill CTAs instead of skeuomorphic/hard-shadow buttons.
- Generous whitespace and an 8pt-feeling spacing rhythm.

## What changed

**Typography** — Replaced "Baloo 2" + "Quicksand" (rounded/playful) with **Fraunces**
(variable optical-size serif, display) + **Inter** (body/UI), matching the reference's
serif-hero / bold-sans-heading / clean-sans-body hierarchy. No leftover references to the
old fonts remain (`grep -n "Baloo\|Quicksand"` returns nothing).

**Design tokens** (`style.css` `:root`) — Formalized what was previously ad hoc into named
tokens: an 8pt spacing scale (`--space-1`…`--space-8`), a radius scale
(`--radius-sm/md/lg/full`), a layered shadow scale (`--shadow-sm/md/lg/glow`), and a
motion scale (`--motion-instant/fast/slow`, plus the existing `--squish` spring easing and
a new `--ease-out`/`--ease-standard`). These are consumed everywhere rather than
redeclared — e.g. `--gradient-accent` is defined once in terms of `var(--calm)`,
`var(--sky)`, `var(--accent)` and auto-resolves correctly under Light, Dark, and Flow
because of normal CSS custom-property cascade resolution; I explicitly removed a
redundant hardcoded re-declaration of it inside the Dark theme block that would have
violated the "no duplicated styling" requirement.

**Restyled components**: header title (gradient-filled Fraunces wordmark, with a
documented `color: var(--ink)` fallback for browsers without `background-clip: text`),
tagline, the "Find calm route" button (flat gradient pill replacing a skeuomorphic 3D
button, with proper hover/active/disabled states), route/tool cards (token-scale radius,
padding, shadow, hover-lift), the nav banner icon (gradient rounded-square badge), and the
Kalimba unlock CTA.

**Dark theme palette** — Replaced the old olive-green dark palette with a deep-navy one
(`#12141F`/`#1A1D2B`/`#232637`) closer to the reference's own dark aesthetic;
`theme-color` in `index.html` and `manifest.json` updated to match.

**Everything else "for free"** — Settings sheet, arrival screen, error banner, pills,
sliders, and toggles were **not** touched directly in this pass, because they already
consumed the semantic token set from an earlier accessibility/design-token pass in this
codebase. I verified live (screenshots in Light/Dark/Flow, plus High Contrast) that they
inherit the new typography and palette correctly with zero component-specific CSS added —
this is the payoff of a real token system rather than scattered hardcoded values.

## Kalimba / Echo functional change

Per your instruction, the Kalimba is now a standalone, always-available instrument; only
*leaving an Echo* requires the pre-existing 500m/3-minute exploration unlock
(`explorationtracker.js` — unchanged, it was already correct).

- `echoUnlockCta` is now always visible, labeled "🪕 Play the Kalimba" (was previously
  hidden until unlock and labeled "✨ Leave a Calm Echo"), and always opens the overlay.
- The Record button (`echoRecordBtn`) is what's actually gated now — new
  `refreshEchoRecordGate()` in `app.js` disables it and adds a `.locked` class until the
  unlock condition is met.
- Added the missing `.echo-record-btn.locked` CSS (this was referenced by the new JS but
  had no styling — caught and fixed during verification): muted background, reduced
  opacity, `cursor: not-allowed`.
- Verified live: overlay opens pre-unlock, all 11 kalimba tines are playable, Record
  renders visibly locked/disabled, and the "Leave this Echo" save button is independently
  disabled too (it was already wired to the same gate).

## Verification performed

- Live browser check in Light, Dark, Flow, and Flow+High-Contrast — confirmed palette,
  typography, gradient-text fallback behavior (High Contrast correctly flattens
  `--gradient-accent` to a solid, pre-chosen-for-contrast accent color, so the header
  title never becomes a low-contrast gradient in that mode).
- Confirmed `prefers-reduced-motion` and the in-app Reduced Motion toggle are unaffected
  (pre-existing global `* { animation-duration: 0.001ms !important; ... }` rule untouched).
- Checked tablet-width (768px) layout: content correctly stays centered via the existing
  `max-width: 480px; margin: 0 auto`, not stretched full-bleed.
- Full test suite: **257/257 passing**, no regressions from either the visual or
  functional changes.
- One real service-worker gotcha hit during verification, not a code bug: a previously
  installed service worker was serving stale cached CSS in the dev browser, which is
  exactly the cache-versioning behavior `sw.js` documents — confirms why `CACHE_NAME`
  must bump on every deploy that touches `APP_SHELL` files.

## Files modified

- `style.css` — token system, typography, dark palette, component restyling, new
  `.echo-record-btn.locked` state.
- `index.html` — font links, `theme-color`, `echoUnlockCta` markup/copy.
- `app.js` — `refreshEchoRecordGate()`, simplified unlock-CTA wiring.
- `manifest.json` — `background_color`/`theme_color`.
- `sw.js` — `CACHE_NAME` bumped to `v16` (this file is in every deploy's `APP_SHELL`
  bump list; bumping it is what forces existing installs to pick up the new shell).
