# Native Setup — Calm Navigation Companion (iOS + Android via Capacitor)

This document covers building and opening the native apps. For what the background navigation feature actually does on each platform, see [IOS_BACKGROUND_NAVIGATION.md](IOS_BACKGROUND_NAVIGATION.md) and [ANDROID_BACKGROUND_NAVIGATION.md](ANDROID_BACKGROUND_NAVIGATION.md).

## Architecture at a glance

The web app (vanilla HTML/CSS/JS, still deployed as-is to Cloudflare Pages) is wrapped in [Capacitor](https://capacitorjs.com) rather than rewritten. A custom Capacitor plugin, **CalmNavBackground** (`plugins/calm-nav-background/`), does the one thing the web platform genuinely cannot: keep GPS tracking, off-route/arrival detection, voice guidance, and lock-screen controls running while the phone is locked or the app is backgrounded.

```
calm-navigation-companion/
├── index.html, app.js, ...        Existing web app — unchanged behavior, deployed to Cloudflare Pages as-is
├── shared/                        Platform-agnostic interfaces + pure logic (route payload building, reroute
│                                   backoff, foreground-reconciliation) — unit-tested, no DOM/native calls
├── web/                            Web implementations of those interfaces (navigator.geolocation, the
│                                   existing AudioManager/VoiceEngine/HapticManager, Page Visibility API)
├── native/                         Native implementations — call into the CalmNavBackground plugin (and the
│                                   official @capacitor/app / @capacitor/haptics plugins)
├── plugins/calm-nav-background/    The custom plugin itself: TS definitions, Swift (iOS), Kotlin (Android)
├── scripts/build-web.sh            Builds www/ (the Capacitor webDir) from the project's source files
├── www/                            Generated by build-web.sh — gitignored, never hand-edited
├── ios/, android/                  Generated by `npx cap add ios|android` — native projects
└── capacitor.config.ts             appId, appName, webDir
```

`app.js` talks to a single seam — `NavBridge` (`shared/navigationBridge.js`) — for everything location/audio/speech/haptics/lifecycle/notification-related. `NavBridge.isNative` picks the web or native implementation of each interface at startup. This is what guarantees there is never more than one engine processing the same GPS stream (see IOS_/ANDROID_BACKGROUND_NAVIGATION.md's "single-engine invariant").

## Why Capacitor (not React Native / Flutter)

The existing app is a working, tested, ~20-file vanilla JS/HTML/CSS project with zero build step. Capacitor wraps it in a real native shell (WKWebView / Android WebView) without requiring a rewrite — the UI, routing logic, audio engine, and haptic engine are all reused untouched. React Native or Flutter would mean re-implementing the entire UI and every engine (`navlogic.js`, `ambientengine.js`, `gestureengine.js`, etc.) in a different language/framework — a full rewrite, not justified here since Capacitor's plugin system is sufficient to reach true background GPS/audio/notifications (the actual gap a plain PWA has). A custom native plugin (Swift + Kotlin) was written specifically because no existing Capacitor plugin combines background navigation-grade location, native TTS, and lock-screen controls in one place — see the two background-navigation docs for exactly what it does.

## Prerequisites this was authored without

This project was built out (config, Swift, Kotlin, JS) on a Mac that has **only Xcode Command Line Tools, no full Xcode, no CocoaPods, no Android Studio/SDK, and no Java runtime** — meaning none of the native code here has been compiled, run in a simulator/emulator, or tested on a physical device. Before doing anything below, install:

- **Xcode** (full app, from the Mac App Store) — Command Line Tools alone are not enough to build an iOS app.
- **Android Studio** (includes the Android SDK and a bundled JDK) — or a standalone JDK 17+ and the Android SDK command-line tools if you prefer not to install the full IDE.
- **CocoaPods is NOT required** — this project's iOS plugin integration uses Swift Package Manager exclusively (Capacitor 8's default; no `Podfile` is generated). `pod install` is not part of this workflow.
- An **Apple Developer account** ($99/year) to run on a real iPhone or submit to the App Store (a free account lets you run on your own device for 7 days at a time via Xcode, but not submit to the store).
- A **Google Play Console account** ($25 one-time) only needed for Play Store submission — running a debug build on your own Android phone needs neither an account nor a fee.

## One-time setup

```bash
npm install
```

(Already done in this repo — `package.json` includes `@capacitor/core`, `@capacitor/cli`, `@capacitor/ios`, `@capacitor/android`, `@capacitor/app`, `@capacitor/haptics`, `@capacitor/preferences`, and the local `calm-nav-background` plugin via a `file:` dependency.)

The `ios/` and `android/` native projects already exist in this repo (created via `npx cap add ios` / `npx cap add android`). You should not need to re-run `cap add` — only `cap sync` (below) after pulling changes or editing native/plugin code.

## Building and opening the projects

```bash
npm run cap:sync    # builds www/, builds the plugin's TS, then `cap sync` (copies web assets + native plugin refs into both platforms)
npm run ios:open    # cap:sync, then opens ios/App/App.xcodeproj in Xcode (SPM-based — no .xcworkspace/CocoaPods here)
npm run android:open # cap:sync, then opens the android/ project in Android Studio
```

Exact manual equivalent, if you'd rather run each step yourself:

```bash
npm run build:web              # scripts/build-web.sh: rebuilds www/ from the source files
npm run build:plugin           # compiles plugins/calm-nav-background's TypeScript (tsc)
npx cap sync                   # copies www/ into both native projects, re-links the plugin
npx cap open ios               # opens Xcode
npx cap open android           # opens Android Studio
```

**Every time you change a file under `shared/`, `web/`, `native/`, or any existing app file** (`app.js`, `index.html`, etc.), re-run `npm run cap:sync` before building in Xcode/Android Studio — the native projects only see what's in `www/`, which is a generated copy, not a live reference to the source files.

**Every time you change Swift/Kotlin inside `plugins/calm-nav-background/`**, re-run `npx cap sync` (Xcode/Android Studio pick up the new source directly on next build — no separate compile step needed for the native code itself, only for the plugin's TypeScript definitions).

## What was verified in this environment vs. what still needs a real Mac with Xcode/Android Studio

Verified here (no Xcode/Android SDK required for these):
- `npx cap add ios` / `npx cap add android` completed successfully; both platforms build a valid project structure.
- The custom plugin is correctly linked into both: confirmed present in `ios/App/CapApp-SPM/Package.swift` and `android/capacitor.settings.gradle`/`android/app/capacitor.build.gradle`.
- The plugin's TypeScript (`plugins/calm-nav-background/src/*.ts`) compiles cleanly (`tsc --noEmit`, zero errors).
- No API secret appears anywhere under `ios/`, `android/`, `www/`, or `plugins/` (grepped for the key pattern and for any copy of `.dev.vars`).
- All 119 `node --test` unit tests pass, including the new shared-logic tests.
- App icons and splash screens were generated for both platforms from the existing `icon-512.png` via `@capacitor/assets` — **note: 512×512 is below Apple's recommended 1024×1024 source for the App Store marketing icon; regenerate from a higher-resolution source (`assets/icon.png`) before a real App Store submission, or the icon will look soft.**

**Not verified — genuinely requires Xcode/Android Studio + a physical device, none of which exist in this authoring environment:**
- Whether `ios/` actually compiles in Xcode (`xcodebuild` here fails immediately: *"active developer directory ... is a command line tools instance"* — full Xcode isn't installed).
- Whether `android/` actually compiles with Gradle (`./gradlew tasks` here fails immediately: *"Unable to locate a Java Runtime"* — no JDK installed).
- Whether the app runs at all on a simulator/emulator or physical device.
- Whether locked-screen GPS and locked-screen audio genuinely work — **this is the core claim of the whole feature, and it has only been implemented and statically reviewed, never run.** See MOBILE_TESTING_CHECKLIST.md for the exact steps to verify this yourself, which you must do before trusting this on a real trip.

## Environment / configuration

No new secrets. The GraphHopper API key remains a Cloudflare Pages secret, read only by `functions/api/*.js` — the native app never has it, calling the exact same `https://calm-navigation-companion.pages.dev/api/route` and `/api/geocode` endpoints the web app does (see `config.js`'s `NATIVE_API_BASE_URL`, and `functions/api/*.js`'s new CORS header, added because the native app's WebView origin differs from the Cloudflare Pages origin, making these cross-origin calls).

If you fork this and deploy your own Cloudflare Pages site, update `config.js`'s `NATIVE_API_BASE_URL` to match your own deployed URL — it's a plain non-secret config value, safe to commit.

## Production vs. development

- **Development**: `npm run ios:open` / `npm run android:open`, run the Debug configuration from Xcode/Android Studio, install to a device via a USB cable or wireless debugging.
- **Production**: bump `capacitor.config.ts`'s version metadata and the native projects' own version/build numbers (Xcode's target settings / `android/app/build.gradle`'s `versionCode`/`versionName`), archive (Xcode: Product → Archive) or build a signed release bundle (Android Studio: Build → Generate Signed Bundle), then submit through App Store Connect / Google Play Console. Both require the developer accounts named above and are entirely manual steps this environment cannot perform.
